## 概要

複数の AI モデルを1つの API で使えるようにする仲介サービス **OpenRouter** が、**3つの推論事業者をプラットフォームから外し、125のエンドポイントを「データを保存しない（ZDR）」対象から外した**と The Hacker News が11月22日に報じました。きっかけは、セキュリティ企業 **Dragos** が約200万件のプロンプトに追跡用の「おとり」の秘密情報を仕込んで行った調査で、少なくとも3つの推論事業者から数か月にわたってデータが盗まれていたことが分かりました。関連して、推論事業者の **Together AI** も、AI コーディングエージェントが認証情報を公開リポジトリに載せたことでプロンプトの一部が流出したと公表しています。

- **発表元**：OpenRouter（報道：The Hacker News）、Dragos、Together AI
- **発表日**：2026/11/22（報道日）
- **ポイント**：安価な推論事業者や仲介サービス経由で、プロンプト内の秘密情報が読まれていた

## このニュースの影響

- **エンジニア・開発者**：プロンプトに API キーなどの秘密情報が含まれると、経由する事業者の側で盗まれるおそれがあることが具体的に示されました。Dragos は、一次の提供元へ直接つなぐ、利用する事業者を自分で選ぶ、おとりの認証情報を仕込んで使われたら事故として扱う、といった対策を勧めています。
- **企業・ビジネス**：「データを保存しない」設定でも実際に守られているとは限らないことが分かり、AI の利用先を選ぶ際に、委託先や経路まで含めた確認が必要になると考えられます。
- **一般の利用者**：AI サービスに入力した内容が、表に出ない事業者を経由して処理される場合があるため、機密性の高い情報を入力する際には注意が必要です。

## 詳しく

- **Dragos の調査**（11月19日公開）：2026年7月〜11月に、URL や DNS 名、AWS のキーなどのおとりを仕込んだ約200万件のプロンプトを広く使われる AI サービスに送り、その後に使われるかを監視しました。
  - 少なくとも3つのホスティング事業者からデータが盗まれており、最も早いものは7月中旬に始まっていました。最大の事案では、10月下旬に送った数百件の AWS キーが盗まれました。おとりのキー全体では、盗まれた認証情報で数万回の AWS API 呼び出しが行われました。
  - 推論のマーケットプレイスでは、再販業者が通常のログ機能だけで顧客のプロンプトを閲覧・保持できたとしています。
  - ある中国の AI ラボは、7月〜10月に自社モデルへ送られたプロンプトの半分以上から秘密の URL にアクセスしており、ZDR 指定のリクエストでも約3分の2が対象だったと報告しています。
  - 約2,000の経路を調べたところ、数百の経路に正体不明のシステムが含まれていました。
  - 被害を受けた事業者の名前は公表されていません。
- **OpenRouter の対応**：The Hacker News によると、3つの事業者を除外し、125のエンドポイントを ZDR の対象から外して、影響を受けた可能性のある顧客に通知しました。125件には、問題が指摘された事業者のほか予防的に外したものも含まれます。OpenRouter 自体への侵害はないとしています。除外された3社と Dragos の調査の3社が同じかどうかは明らかにされていません。
- **Together AI の公表**（11月21日）：社内の非公開 Hugging Face リポジトリの認証情報を、AI コーディングエージェントが公開 GitHub リポジトリにコミットしてしまい、第三者が保存済みのプロンプトのサンプルをダウンロードしました。対象は主に2026年6〜7月の MiniMax M3、GLM-5.2、Kimi K2.6 へのリクエストです。侵入者がサンプル内の認証情報を試した際、そのうち5件は Dragos の実験のおとりでした。同社は新規アカウントで ZDR を標準にするなどの対策を取ったとしています。

## なぜ重要か

AI エージェントの普及で、プロンプトに認証情報や社内データが含まれることが増えています。今回の調査は、モデル本体ではなく、その手前の推論事業者や仲介サービスが情報漏えいの経路になり得ることを実測で示しました。AI のサプライチェーン（委託先や経路）全体の安全性が問われる段階に入ったといえます。
