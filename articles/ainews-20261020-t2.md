## 概要

**Microsoft** は2026年10月19日、企業が使う AI エージェントを社員と同じ「内部の存在（インサイダー）」とみなして守るための、**セキュリティ機能群** を発表しました。中心となるのは、セキュリティ対応を自動で進めるエージェント群 **「Guardian Agents」** です。同社は、エージェントは本質的に悪意を持つわけではないものの、誤りを犯したり、操られたり、乗っ取られたりする可能性があるとしています。

- **発表元**：Microsoft
- **発表日**：2026/10/19
- **ポイント**：エージェントの監視・権限管理を、モデル提供元から切り離して企業側で行う仕組み

## このニュースの影響

- **エンジニア・開発者**：Claude Code や OpenAI Codex、GitHub Copilot など、手元の PC で動くエージェントも検出・登録の対象になります。社内で使うエージェントに、作業ごとの最小限の権限しか与えられない運用が広がる可能性があります。
- **企業・ビジネス**：エージェントの一覧管理、リスク評価、高リスク操作への人の承認といった統制を、既存の Microsoft のセキュリティ製品とまとめて扱えるようになります。ただし、各機能のプレビュー・一般提供の時期は公式ブログに書かれておらず、導入時期は今後の発表を確認する必要があります。

## 詳しく

- **Guardian Agents**：同社のセキュリティの取り組み「Project Perception」の一部で、リスクが変わった理由の説明、証拠の調査、封じ込めの提案・実施、ポリシーの見直しを担います。重要な判断は人が持つとしています。
- **エージェントの検出**：Microsoft Defender で検出できるローカルのエージェントを35種類追加し、合計60種類にしました。
- **Entra Agent ID の拡張**：ローカルで動くエージェントや、センサーが見つけた未知のエージェントにも、利用者とは別の ID を割り当てられるようにします。
- **Dynamic Permissions**：エージェントは権限ゼロから始まり、タスクに必要な権限だけをその間だけ受け取ります。利用者本人が持たない権限は得られません。
- **Dynamic Agent Risk / 条件付きアクセス**：ID・データ・端末・クラウドなどの信号からエージェントのリスクを継続的に評価し、書き込みだけ止める、人の承認を求める、実行を止めるといった段階的な対応を取ります。
- ブログは、モデル自身を安全性の判断役にすべきではないというサティア・ナデラ CEO の考え方を引き、アクセスや操作の制御はモデルの外側に置くべきだとしています。

## なぜ重要か

AI エージェントが社内のデータやツールに広くアクセスするようになり、「外部からの攻撃」だけでなく「自社で動かすエージェントの誤動作」への備えが課題になっています。Microsoft は制御をモデルの外側に置く考え方を打ち出しており、エージェントの統制を誰が担うのかという議論に影響を与える可能性があります。
